# Frontend Sub-project Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **UI tasks (Tasks 5–10):** load `frontend-design:frontend-design` before writing any component, layout, or page. It governs Tailwind token usage, shadcn/ui assembly, colour application, and layout patterns.

**Goal:** Build the full React + TypeScript SPA for Explorai — auth, document management, chat with citations, and a live dashboard — backed by two new backend endpoints and a persisted conversation history.

**Architecture:** TanStack Router (file-based, type-safe) + TanStack Query (server state, cache invalidation). Backend extended with a `conversations` table, `GET /api/v1/conversations`, and `GET /api/v1/stats`; `POST /api/v1/ask` auto-saves each exchange. The frontend is a five-route SPA (`/login`, `/signup`, `/dashboard`, `/documents`, `/chat`). Tailwind CSS + shadcn/ui components, colour palette from the spec's Section 9.

**Tech Stack:** React 19, TypeScript ^5, Vite, TanStack Router v1, TanStack Query v5, Tailwind CSS v3, shadcn/ui (Radix UI), Vitest, msw v3; Python FastAPI backend with SQLAlchemy + Alembic.

**Spec:** `docs/superpowers/specs/2026-11-02-frontend-design.md`

## Global Constraints

- TypeScript stays on `^5`; do not upgrade to v7.
- `pnpm` only — no npm or yarn commands.
- All new backend routes follow the exact same pattern as `api/documents.py`: router, service, repository, deps injection.
- New Alembic migration number: `0007_conversations`.
- RLS policy on `conversations` uses `current_setting('app.current_user_id')::uuid`, identical to `documents`.
- `POST /api/v1/ask` response schema is **unchanged** — the conversation save is a silent side-effect.
- TanStack Router file-based routing: files in `frontend/src/routes/`; route tree auto-generated to `frontend/src/routeTree.gen.ts`.
- shadcn/ui components installed with `pnpm dlx shadcn@latest add <component>` into `frontend/src/components/ui/`.
- Colour tokens from spec Section 9 applied in `frontend/src/index.css` `:root` block.
- Coverage gate 80% applies to the frontend (`--coverage` in `vitest.config.ts`).
- Every backend test file follows the existing 80% gate in `backend/pyproject.toml`.
- After every new backend route: run `uv run --package explorai-backend python backend/scripts/export_openapi.py` then `pnpm --dir frontend gen:api` and commit both generated files.

## Review Focus

- **401 during a page** — any Query that receives a 401 after the app has loaded must clear the entire Query cache and redirect to `/login`, not just show an error; test this in the app-shell test by simulating a mid-session 401 on `/api/v1/documents`.
- **PII-blocked document** — the "Ask about this document" link must be absent (not disabled) when `pii_blocked: true`; test that the link node does not appear in the rendered row.
- **`insufficient_evidence` answer** — the amber callout must render and no error state should appear; the Send button must re-enable so the user can ask again; test both.
- **`/chat?documentId=<id>` pre-population** — the document selector must be pre-populated from the search param on mount; test that the selector's value matches the param after render.
- **Empty conversations list** — the history panel must render a zero-state message ("No conversations yet") rather than an empty list or crash; test with an empty `items` array from the mock.
