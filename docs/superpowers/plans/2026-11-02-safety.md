# Safety Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a safety layer to Explorai: PII detection at ingestion and output, prompt injection defence (pattern cascade + LLM-as-judge), and a versioned adversarial test suite in CI.

**Architecture:** All safety logic lives as flat modules in `ai/src/explorai_ai/` (consistent with ADR 0005). `AnswerPipeline` gains two optional filter hooks. The ingestion pipeline (`chunk_pending_versions`) scans sections for PII before chunking; the `pii_action` ("block"/"redact") is stored on the `Document` record and read at processing time.

**Tech Stack:** Python 3.12, presidio-analyzer + presidio-anonymizer (optional, spacy en_core_web_sm), regex fallback when presidio absent, pytest, FastAPI, SQLAlchemy, Alembic.

**Spec:** `docs/superpowers/specs/2026-11-02-safety-design.md`

## Global Constraints

- All new code in `ai/`, `pipelines/`, `backend/`, `db/` follows existing package patterns (mypy strict, ruff, 80% coverage gate per package).
- presidio packages are **optional** extras in `ai/pyproject.toml`; the regex fallback path is always tested in CI (no presidio installed in the standard test run).
- New migration is `0006_pii_redacted.py`; it adds two nullable-with-default columns to `documents`.
- `PiiScanner` is lazy-initialised: the presidio engine is not created at import time.
- The `input_filter` and `output_filter` hooks in `AnswerPipeline` default to `None`; existing tests must pass unchanged.
- No PII text (matched strings) ever appears in error responses, logs, or API responses — only entity type names.
- `pii_action` values: `Literal["block", "redact"]`; default `"block"`.
- Document version statuses (existing): `"ok"`, `"failed"`, `"unextractable"`. New status: `"pii_blocked"`.

## Review Focus

1. **Unicode homoglyph injection** — `Ｉｇｎｏｒｅ` (fullwidth) evades ASCII pattern matching; `InputFilter.check()` must NFKC-normalise before matching. → `test_safety_input.py::test_homoglyph_injection_is_blocked` (Task 2).
2. **PII in citation quotes** — a citation quote field contains `john@example.com`; `OutputFilter.check()` must scan quote strings, not only the answer text. → `test_safety_output.py::test_pii_in_citation_quote_is_caught` (Task 3).
3. **LLM-as-judge returns unexpected string** — `"This looks benign"` instead of `"NO"`; the parser must treat anything that is not exactly `"YES"` as allow. → `test_safety_input.py::test_judge_unexpected_response_is_allow` (Task 2).
4. **Residual `[REDACTED_EMAIL]` marker in generated answer** — the model quotes a redacted chunk verbatim; `OutputFilter` must detect `[REDACTED_*]` patterns as PII markers. → `test_safety_output.py::test_redacted_marker_in_answer_is_caught` (Task 3).
5. **Empty text in PII scan** — `PiiScanner.scan("")` must return `ScanResult(has_pii=False, entities=(), redacted_text="")` without raising. → `test_pii.py::test_scan_empty_string` (Task 1).

### Task 6: Ingestion PII hook

**Ruling:** The spec assumes a synchronous 422 at upload time; text extraction is async in `process-pending`. PII blocking is therefore async: `chunk_pending_versions()` reads `pii_action` from the document record, and if PII is detected with `action="block"`, the version is not chunked and `Document.pii_blocked` is set to `True`.

**Files:**
- Create: `pipelines/src/explorai_pipelines/errors.py`
- Modify: `pipelines/src/explorai_pipelines/indexing.py` (`chunk_pending_versions`)
- Modify: `pipelines/src/explorai_pipelines/repository.py` (expose `pii_action` on `VersionToChunk`; add `mark_pii_blocked(document_id)`)
- Test: `pipelines/tests/unit/test_indexing_unit.py` (extend)
