# RAG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user ask a question and get an answer built only from documents they may read, with citations verified verbatim by our code and a refusal when the corpus lacks the information.

**Architecture:** A new library package `ai/` (`explorai_ai`) holds the RAG logic: chunking, provider interfaces with fakes and real adapters (Claude, Voyage), a Qdrant index, a `Retriever` and an `AnswerPipeline`. PostgreSQL stays the source of truth (`chunks` table, row-level security); Qdrant holds only vectors, ids and `owner_id`. `pipelines/` indexes (chunk, embed, upsert, prune) through Prefect deployments; `backend/` serves `POST /api/v1/ask`. `ai/` depends on `db/` only, never on `backend/` or `pipelines/` (ADR 0005).

**Tech Stack:** Python 3.12, qdrant-client, anthropic SDK, httpx (Voyage REST), SQLAlchemy 2.0, Alembic, Prefect 3, FastAPI, pytest, ruff, mypy strict; Qdrant in Docker Compose and as a CI service.

**Spec:** `docs/superpowers/specs/2026-11-01-rag-design.md` (read it first). Conventions continue from `docs/superpowers/plans/2026-11-01-core-backend.md`.

## Global Constraints

- English in the repo; each task has a **Concept** line, turned into `docs/concepts/03-rag.md` in Task 12.
- GitFlow: work on `feature/rag` (spec already committed). Conventional Commits ending with the trailer the session instructs. Never push, open a PR or change GitHub settings without the user's approval. **Check the CI results before anyone merges** (lesson of the previous sub-project: a PR was merged with no CI job having run).
- Quality bar per package: `ruff`, `mypy --config-file <package>/pyproject.toml` (strict), `pytest` with the 80% gate, one call per package. New packages get the same `pyproject.toml` pattern as `db/` and `pipelines/`.
- Dependency lock lessons: new dependencies must be locked and the three existing suites re-run; Prefect 3.8 forces `fastapi<0.154` and `sqlalchemy<2.1` (root `pyproject.toml` constraints). If a new dependency conflicts with those, stop and report.
- Tests never touch the network and never need an API key: all providers are replaced by the fakes of Task 1 (`RAG_PROVIDER=fake`). Real keys are never in the repo, in Compose files, or in CI. The agents must not enter or request real keys.
- Secrets (`ANTHROPIC_API_KEY`, `VOYAGE_API_KEY`, `QDRANT_API_KEY`) are `SecretStr`, never in responses, logs or validation errors (`hide_input_in_errors=True`). Neither questions nor document text are written to logs: ids, counts and durations only.
- CI workflow: never use the `runner`/`env` contexts in job-level `env` (it invalidates the workflow); use fixed paths.
- Fixed values: refusal levels as in the spec; question at most 2000 characters; 30 questions per hour per user; candidates 50 dense + 50 sparse, 30 after fusion, 8 after reranking; chunk window 400 words with 60 words of overlap; at most 500 chunks per document; sections under 5 words are skipped; advisory lock keys `INDEX_LOCK = 4242002` and `PRUNE_LOCK = 4242003` (the existing catch-up key is `4242001`); `index-pending` every 30 s, `prune-index` every 3600 s; Qdrant alias `chunks_current`; the public corpus payload value is `"public"`.
- Model defaults (settings, all overridable): generation `claude-sonnet-5-5`, query rewriting `claude-haiku-5-5`; the Voyage embedding and rerank model names and the embedding dimension are set in Task 5 after checking the provider's current documentation (the plan does not guess them).
- Plan-level choices (not in the spec): the sparse vectors are produced by our own code (token hashing and BM25-style term weights, with Qdrant's IDF modifier applied at query time) instead of a download-on-first-use model, so tests, CI and containers need no model download; Voyage is called over REST with `httpx` (testable with `MockTransport`), Anthropic through its official SDK with an injectable client; `chunks` gets a `chunked_at` marker on `document_versions` so a version with zero chunks is not re-chunked forever; chunk rows of old versions are kept (removed by cascade with their version), only Qdrant points are pruned.

## Review Focus

1. A chunk of another owner, a deleted document or a non-latest version must never reach the prompt, even when Qdrant returns it. (Tasks 3, 7, 9)
2. A citation whose quote is not verbatim in its source, or whose source number is out of range, is dropped; if none survives the answer becomes a refusal. (Task 7)
3. An empty corpus or a question with no match gives `insufficient_evidence` (`200`), never `500`; a provider or Qdrant outage gives `503`, not a refusal. (Tasks 7, 8)
4. During an embedding-model change the alias keeps serving the old collection until the new one is fully indexed. (Tasks 4, 6)
5. A chunk containing text such as `</source>` or "ignore previous instructions" cannot break out of its tag, and the prompt stays within the bounded candidate count. (Task 7)

### Task 2: Chunking, sparse encoder, scope filter (pure units)

**Files:**
- Create: `ai/src/explorai_ai/{chunking.py,sparse.py,scope.py}`
- Test: `ai/tests/unit/test_chunking.py`, `test_sparse.py`, `test_scope.py`

**Interfaces:**
- `chunking`: `SectionInput(heading: str | None, text: str)`; `chunk_sections(sections: Sequence[SectionInput], *, target_words: int, overlap_words: int, max_chunks: int) -> list[ChunkText]`; `ChunkText(ordinal: int, heading: str | None, text: str, word_count: int)`; `embedding_text(heading: str | None, text: str) -> str` (heading, newline, body; used for both dense and sparse input). Windows slide by `target_words - overlap_words`, never cross a section, the last window may be shorter, sections under 5 words are skipped, `ordinal` counts chunks across the document from 0, output stops at `max_chunks`. `text` holds the body only (the heading is not repeated in it).
- `sparse`: `SparseVector(indices: list[int], values: list[float])`; `encode_document(text: str) -> SparseVector` (lowercase word tokens, 32-bit stable hash of each token via `hashlib.blake2b`, values `tf * (k1 + 1) / (tf + k1)` with `k1 = 1.2`, one entry per distinct token, indices sorted); `encode_query(text: str) -> SparseVector` (distinct tokens, value 1.0). Qdrant applies IDF.
- `scope`: `PUBLIC_OWNER = "public"`, `Scope = Literal["all","mine","public"]`, `build_scope_filter(user_id: uuid.UUID, scope: Scope = "all", document_id: uuid.UUID | None = None) -> qdrant_client.models.Filter`. It is the **only** function in the repo that builds a Qdrant filter: `all` matches `owner_id` in `[str(user_id), "public"]`, `mine` only the user id, `public` only `"public"`; `document_id` adds a `document_id` match. The owner condition is always present.

**Concept:** chunk size and overlap trade-offs, BM25 term weighting, why one function builds the filter.

### Task 7: Retriever, citation verification, `AnswerPipeline`

**Files:**

**Interfaces:**
- `citations`: `normalise_for_match(text: str) -> str` (Unicode NFKC, case-folded, whitespace collapsed); `Citation(source: int, quote: str, chunk_id: UUID, document_id: UUID, document_title: str | None, heading: str | None)`; `verify_citations(raw: Sequence[RawCitation], candidates: Sequence[Candidate]) -> list[Citation]` (source numbers are 1-based positions in `candidates`; a citation survives only if the source number is valid and `normalise_for_match(quote)` is a non-empty substring of `normalise_for_match(candidate.text)`; duplicates of the same (source, quote) are merged).
- `retriever`: `Candidate(chunk_id, document_id, version_id, document_title, heading, text, score)`; `RetrievalResult(candidates: list[Candidate], best_score: float | None)`; `rrf_fuse(rankings: Sequence[Sequence[UUID]], *, k: int = 60) -> list[UUID]`; `Retriever(*, index: QdrantIndex, embedder, reranker, generator, store: ChunkStore, settings: RagSettings)` with `retrieve(user_id: UUID, question: str, scope: Scope = "all", document_id: UUID | None = None) -> RetrievalResult`: (1) if `rewrite_enabled`, `generator.rewrite_queries(question, 3)` (any `ProviderError` falls back to the question alone) and the question is always included; (2) per query: embed (`embed_query`), `encode_query`, `index.search(... build_scope_filter(user_id, scope, document_id) ...)`; fuse queries with `rrf_fuse` and keep `fused_candidates`; (3) `store.hydrate(user_id, ids)` and reorder by fused rank (missing ids dropped); (4) if `rerank_enabled`, `reranker.rerank(question, texts, final_candidates)` (a `ProviderError` falls back to fused order truncated to `final_candidates`, logged without text) and `best_score` is the top rerank score, else `best_score` is `None`. Query-embedding or Qdrant failure raises `RetrievalUnavailable`; an empty result is a valid `RetrievalResult([], None)`.
- `pipeline`: `AskOutcome` is `AnswerResult(status: Literal["answered","insufficient_evidence"], answer: str | None, citations: list[Citation], usage: Usage)` (in `ai.models`); `AnswerPipeline(retriever, generator, settings)` with `ask(user_id, question, scope="all", document_id=None) -> AnswerResult`: no candidates, or `rerank_enabled` and `best_score < refusal_threshold` → `insufficient_evidence` **without calling the generator**; otherwise builds `PromptSource` list (neutralised), calls `generator.answer`, maps `insufficient` to `insufficient_evidence`, and for `answered` runs `verify_citations`; no surviving citation → `insufficient_evidence` (answer `None`); generation `ProviderError`/`ProviderUnavailable` propagates as `RetrievalUnavailable`-style `ProviderUnavailable` (the route turns it into `503`).
