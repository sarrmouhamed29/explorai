# 0008. A shared `db/` package owns the schema

- Status: Accepted, amended on 2026-11-01 (see "Amendment" below)
- Date: 2026-10-31

## Context

Two Python packages need the same tables: the ingestion pipelines write documents, and the core backend (sub-project 2) will read them and add users. If the schema lived in `backend/`, the pipelines would depend on the API package, which breaks the rule that batch code does not go through the API (see ADR 0005 for the same principle applied to `ai/`).

## Decision

Create the workspace package `db/` (`explorai-db`). It holds the SQLAlchemy models, the engine and session helpers, and the Alembic migrations, which live inside the package (`explorai_db/migrations`) so that they ship with it in any install. `pipelines/` depends on `db/`; the backend will adopt it when it needs the schema. `python -m explorai_db.migrate` upgrades the database named in `DATABASE_URL`; a one-shot Compose service runs it before the pipelines start. `explorai_db.testing.temporary_database` creates a throwaway migrated database for integration tests.

## Alternatives considered

- **Schema inside `backend/`.** Fewer packages, but pipelines would import the API package, and any API refactor would risk the ingestion code.
- **Each package owns its tables.** Independence, but two migration histories on one database and a duplicated model of the same rows.
- **No ORM, plain SQL files.** Transparent, but loses typed models and autogenerated migration diffs; the schema is small enough that the ORM is not a burden.

## Consequences

- One migration history for the whole database, with a single owner.
- The schema is shared state: changes need a migration and a check that both consumers still work. A test (`test_models_match_migrations`) fails when models and migrations diverge.
- `owner_id` is a plain nullable UUID without a foreign key until the `users` table exists in sub-project 2.

## Amendment (sub-project 2, 2026-11-01)

`db/` is the **persistence layer**, not only the schema: it also holds the blob store and the identity-scoped session helper.

- `BlobStore` and `LocalBlobStore` moved from `pipelines/` to `explorai_db.blobs`, because the API now writes uploaded files and must not import the pipelines package. This is the same argument as the original decision, applied to bytes instead of rows. The store gained `keys_older_than` and `delete_if_older_than` for garbage collection, and `put` refreshes the age of an existing blob.
- `explorai_db.rls.scoped_session` is the only way request code opens a transaction (ADR 0010).
- Migration 0003 adds `users`, turns `owner_id` into a foreign key, adds the `explorai_app` role, its grants and the RLS policies; migration 0004 adds `documents.created_at`. The consequence above about `owner_id` is therefore resolved.
- `make_engine` hides SQL parameters from error messages, so a failing statement can never put a password hash in a log.
- The backend adopted the package, as announced. Both consumers still depend on `db/`, and `db/` depends on neither.
